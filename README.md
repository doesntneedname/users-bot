# users-bot — объявления о приходе и уходе сотрудников

Слушает исходящий вебхук Пачки (`company_member`) и пишет в чат
**«Доступы»** (`144223`): «Встречаем нового сотрудника …» и «Прощаемся с …»,
а в тред к сообщению — упоминания тех, кто выдаёт и отзывает доступы.

## Как работает

```
Пачка ──webhook──► POST /employee ──┬── invite  → очередь на диске → воркер → объявление
                                    ├── suspend → проверка → объявление сразу
                                    └── activate/confirm/прочее → только лог
```

* **invite** объявляем не сразу: даём HR время заполнить карточку (теги
  нужны, чтобы позвать в тред нужных людей). Ждём `INVITE_DELAY_MINUTES`,
  дальше проверяем раз в минуту, пока карточка не заполнится, но не дольше
  `INVITE_DEADLINE_HOURS` — потом объявляем как есть.
* **suspend** объявляем сразу и снимаем висящее приглашение, если оно было.
* Очередь и журнал доставок лежат в `STATE_PATH` (volume), поэтому
  переживают перезапуск контейнера.

## Кого считаем сотрудником

Решает `src/filter.js`. Главный признак — почта: `фамилия@pachca.com`.
Отсекаются плюс-алиасы (`dekina+1@pachca.com`), внешние домены, боты,
имена со словами «тест/demo/guest» и имена с цифрами и мусорными символами.

Так лечатся два реальных пролёта старого фильтра, который смотрел только на
имя: **«not me»** (06.08.2026) и **«L;ekbz ДмитриевнаВнааа Алесандровга»**
(09.09.2026) — в первом не было ни «теста», ни спецсимволов, во втором был
символ `;`, которого не было в списке запрещённых.

## Идемпотентность

Пачка доставляет вебхуки **at-least-once**, поэтому каждое событие
запоминается по ключу `тип:событие:user_id:created_at` на `DEDUPE_TTL_HOURS`.
Повтор той же доставки игнорируется, а разные события одного человека
(suspend → activate → suspend) обрабатываются как разные.

## Подпись вебхука

Если задан `PACHCA_WEBHOOK_SECRET` (Signing secret в настройках бота,
вкладка «Исходящий webhook»), проверяется заголовок `Pachca-Signature`
(HMAC-SHA256 от сырого тела). Без секрета проверка выключена, и при старте
пишется предупреждение.

## Запуск

```bash
cp .env.example .env      # заполнить PACHCA_API_TOKEN
docker compose up -d --build
curl localhost:3002/healthz
```

Локально: `npm install && npm start`, тесты — `npm test` (36 тестов,
node:test, без внешних зависимостей).

`DRY_RUN=1` — всё считается и логируется, но в Пачку ничего не уходит;
удобно проверять фильтр на боевом трафике.

## Что изменилось в версии 2 (09.09.2026)

| Было | Стало |

| фильтр по имени, тестовые аккаунты пролезали | гейт по корпоративной почте + эвристики по имени |
| отложенный invite в `setTimeout`, терялся при рестарте | очередь на диске + воркер |

| подпись вебхука не проверялась | опциональная проверка `Pachca-Signature` |

| один файл на 330 строк, без тестов | модули + 36 тестов |
| chat id и упоминания в коде | всё через `.env` |
